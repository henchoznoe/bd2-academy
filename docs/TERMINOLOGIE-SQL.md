## Mots pédagogiques ajoutés

- **Transfert** : présent dans les titres des variantes EX-V1 à EX-V5. Expliquer « refaire le raisonnement sur une donnée modifiée », ou préférer « variante ». Ce n’est pas une notion SQL supplémentaire. À distinguer du transfert réseau, légitime dans les requêtes distribuées.
- **Pairs / peer(s)** : le contenu actuel emploie « pairs ». Préférer « lignes ex æquo (pairs) » à la première occurrence, avec la définition précise ci-dessus. Aucun besoin d’exiger l’anglais.
- **Frame** : l’anglais apparaît dans l’identifiant interne `sql-window-frames`, pas dans le titre affiché. Cet identifiant ne crée pas de difficulté pédagogique ; conserver « cadre de fenêtre » dans l’interface.
- **Fanout / fan-out** : présent dans la leçon et les exercices de dimensionnement de l’examen. Définir « nombre maximal de pointeurs enfants » ; ce nombre **n’est pas l’ordre d du cours**. Préférer le libellé français dans les résultats visibles.
- **Fixture / dataset / reconstitution** : distinguer la provenance et le jeu réellement utilisé. « Jeu de données d’entraînement » suffit dans l’interface. Une reconstitution pédagogique ne reconstitue pas avec certitude l’annexe originale.

## Priorité : ordre d et hauteur dans l’examen

1. **Convention de la professeure** — `3_BArbres.pdf` p.14 : un B-arbre d’ordre **d** contient entre **d et 2d clés** dans les nœuds hors exception de racine ; un nœud de k clés a k+1 pointeurs d’index. Le nombre maximal d’enfants est donc **2d+1**, pas d. La définition du B+arbre p.36 reprend le B-arbre d’ordre d. La p.30 donne l’exemple d=50 pour 100 clés.
2. **Hauteur** — C-IDX p.27 : hauteur 1 = racine seule, hauteur 2 = racine et un niveau supplémentaire. C-IDX p.26 relie les accès aux niveaux ; p.71 distingue `HEIGHT = BLEVEL + 1`. Le site doit répondre en niveaux dans les variantes d’examen.
3. **Énoncé ancien visible** — EX p.6, imprimée 7 : « De quel ordre est le B-arbre index dans cet exemple ? ». EX p.8, imprimée 9 : « ordre max » d’un index dense de type « B-arbre+ », en supposant **autant de clés que de pointeurs dans un bloc**. Les annotations calculent m couples puis **d=m/2** ; ce sont des indices cohérents avec C-IDX, pas un corrigé officiel à recopier sans les hypothèses.
4. **Ajustement des variantes actuelles** — ne pas demander « ordre = maximum d’enfants » sous le même libellé que l’examen. Avec la convention d=2, annoncer au plus 4 clés et 5 enfants pour le modèle habituel. La figure choisie peut être partiellement occupée ; on ne déduit pas la capacité maximale du seul nombre de flèches présentes.
5. **Modèle simplifié de calcul** — avec B=4096,K=20,P=8 : m=floor(B/(K+P))=146 couples, donc **d=73** et **146 pointeurs dans ce modèle simplifié**. Avec K=12 : m=204, donc d=102. Ne pas remplacer silencieusement le modèle simplifié par le modèle habituel qui donne 147 enfants dans le premier cas : les hypothèses des calculs de niveaux doivent rester cohérentes. Pour une capacité impaire dans une autre variante, expliciter l’arrondi de d et le respect de 2d clés.

## Autres intitulés de l’ancien examen

- EX p.2 : « formuler en français la **sémantique** de la requête D » ; « code SQL **LDD** » et « ensemble **minimal** des DFs ». Ajouter « LDD (DDL) » à la première présentation du site. La requête D est absente : son sens précis, notamment le sens de l’inégalité, ne se déduit pas avec certitude du manuscrit.
- EX p.3–4 : « couverture minimale », décisions « **retenue / éliminée / simplifiée** ». La preuve demandée de deux façons porte sur une DF **déductible** de F ; dire qu’elle appartient à F+ plutôt que prétendre connaître l’ensemble absent.
- EX p.5 : « algorithme de **synthèse** » et résultats de **chaque étape** ; bonus **2FN** pour chaque relation produite. Ne pas réduire la validation à donner seulement les schémas finaux.
- EX p.6–7 : blocs, pointillés, ordre, hauteur, enregistrements et E/S. L’annexe manque : la légende de la figure choisie doit rester explicite ; les numéros de blocs choisis ne sont pas ceux établis de l’original.
- EX p.8–9 : formules et résultats numériques, « **index dense** », blocs feuilles, changement de taille de clé ou d’enregistrement. Garder les unités et arrondis ; les anciennes règles de notation et d’aide autorisée restent historiques.

## Ne pas élargir le programme

LMD p.37 marque UNPIVOT non vu ; la figure p.122 marque une partie des fonctions analytiques non vues, notamment LEAD/LAG. La syntaxe d’exclusion du cadre p.97 et les références XML ne justifient pas d’ajouter des ateliers obligatoires au-delà du programme. Conserver les mots du support comme repères, expliciter les synonymes utiles et identifier les adaptations de dialecte sans ajouter d’objectifs.
