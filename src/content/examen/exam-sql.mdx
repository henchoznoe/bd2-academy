## Prédire avant d'exécuter

Une fenêtre conserve les lignes détaillées. Le jeu course du site est pédagogique : consulter les tables réellement affichées avant de remplir un résultat. Exemple de demande : conserver les employés, afficher le total global, celui de leur département et leur rang salarial.

```sql
SELECT e_id,ename,salaire,
 SUM(salaire) OVER() AS total_global,
 SUM(salaire) OVER(PARTITION BY deptno) AS total_dep,
 RANK() OVER(ORDER BY salaire DESC NULLS LAST) AS rang
FROM emp;
```

Dans le jeu course de base choisi, Ana et Ben gagnent 2500 et 3500 : leur total départemental est 6000. Dina et Eli gagnent chacun 5500 : ils partagent le rang 1 ; le salaire suivant a le rang 3. Les six salaires connus totalisent 22500 ; le salaire NULL ne contribue pas à SUM. Chloé conserve sa ligne mais le total de sa partition sans salaire connu vaut NULL. Ces nombres illustrent le jeu de base, pas les jeux alternatifs de vérification.

## Expliquer une corrélation

```sql
SELECT e.e_id,e.ename,e.salaire
FROM emp e
WHERE e.salaire > (
 SELECT AVG(q.salaire) FROM emp q WHERE q.deptno=e.deptno
);
```

Pour chaque employé, la sous-requête calcule la moyenne des salaires connus du même département. La comparaison stricte exclut les salaires égaux à cette moyenne. Un salaire NULL ou une moyenne NULL ne produit pas de comparaison vraie. Avec l'égalité ordinaire, deux numéros de département NULL ne se rejoignent pas.

## DDL et dépendances : un autre cas choisi

```sql
CREATE TABLE dept_ex (
 deptno INTEGER PRIMARY KEY,
 dname VARCHAR(40) UNIQUE NOT NULL
);
CREATE TABLE emp_ex (
 e_id INTEGER PRIMARY KEY,
 ename VARCHAR(40) UNIQUE NOT NULL,
 deptno INTEGER REFERENCES dept_ex(deptno),
 taux INTEGER, salaire DECIMAL(12,2), commission DECIMAL(12,2)
);
```

Ces contraintes sont choisies pour cet exercice ; le schéma physique de l'atelier course n'est pas annoncé identique. Les clés de emp_ex sont e_id et ename ; chacune détermine toutes ses colonnes. Dans dept_ex, deptno et dname sont deux clés. Une FK garantit une référence valide pour une valeur non NULL ; elle ne dit pas qu'un département possède un seul employé. Il serait faux d'en tirer deptno déterminant e_id.
