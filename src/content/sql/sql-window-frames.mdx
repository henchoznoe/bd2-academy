## Cadres ROWS et RANGE

Le ORDER BY de OVER fixe l'ordre de calcul dans une partition ; il ne garantit pas le tri final affiché. Le cadre précise les lignes participant au calcul pour chaque ligne courante.

```sql
SELECT compte,id,val,
 SUM(val) OVER(PARTITION BY compte ORDER BY id
 ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS solde
FROM t ORDER BY compte,id;
```

Pour un compte avec les valeurs +20 puis -10, le cumul est 20 puis 10. À la partition suivante, le calcul redémarre. UNBOUNDED PRECEDING indique le début de partition, CURRENT ROW la ligne courante. `ROWS BETWEEN 1 PRECEDING AND CURRENT ROW` additionne au plus deux lignes ; avec AVG, c'est une moyenne mobile.

ROWS raisonne en positions physiques dans l'ordre ; RANGE raisonne selon les valeurs de la clé de tri et inclut les pairs. Pour des lignes `(ordre=1,val=10),(ordre=1,val=20),(ordre=2,val=5)`, un cumul RANGE donne 30,30,35. Un cumul ROWS avec ordre déterministe donne 10,30,35.

Dans les cas étudiés, le cadre implicite d'un agrégat avec ORDER BY est généralement RANGE du début à la ligne courante. L'équivalence avec un ROWS explicite n'est pas générale en présence d'ex æquo, même si l'exemple du support sans doublon donne le même résultat.
